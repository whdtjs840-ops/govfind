# Product Quality Audit After 3,088 Policies

작성일: 2026-05-28

## 전체 평가

GovFind는 3,088개 public search-index 기준으로 검색, 번호형 페이지네이션, 상세 페이지 기본 구조, SEO/meta, 공식 출처 안내가 전반적으로 유지되고 있다. `/support/` 목록은 30개 단위 번호형 페이지네이션이 정상 동작하고, 검색 결과 요약과 0건 안내도 사용자가 현재 상태를 이해할 수 있는 수준이다.

다만 3,088개 버전을 바로 production에 배포하기 전에는 기업마당 2차 배치에서 다시 유입된 명백한 카테고리 오분류를 먼저 정리하는 것이 좋다. 특히 기업지원·수출·융자·기술지원 성격의 Bizinfo 정책 26건이 `주거` 카테고리에 들어가 있어, 사용자가 카테고리 탐색을 신뢰하기 어렵게 만들 수 있다.

판단: `배포 전 수정 권장`. 기술적 배포 차단은 없지만, 제품 신뢰도 관점에서 카테고리 정리 후 배포하는 편이 안전하다.

## 메인 페이지 평가

첫 화면은 사이트 목적이 비교적 명확하다. "나에게 맞는 지원금을 찾아보세요"라는 headline과 검색창, 인기 검색어, 카테고리 카드가 있어 공공 지원 포털로서의 첫인상은 안정적이다. 총 3,088건 수치와 카테고리별 count도 신뢰감을 준다.

개선점은 최신 지원사업 카드 구성이 다소 데이터 원문 중심으로 보인다는 점이다. 복지/기업/청년이 한 화면에 섞여 노출되면서 "GovHelp 같은 통합 포털" 느낌은 나지만, 사용자의 첫 탐색 목적에 맞춘 큐레이션은 아직 약하다.

평가:
- 신뢰감: 양호
- 검색창 명확성: 양호
- 카테고리 구성: 대체로 양호, Bizinfo 오분류 수정 필요
- 포털 느낌: 양호

## 목록 페이지 평가

`/support/`는 30개씩 번호형 페이지네이션이 적용되어 3,088개 규모에서도 초기 렌더링이 안정적이다. 검색/필터 적용 시 결과 count, 표시 범위, pagination이 함께 유지된다.

좋은 점:
- `/support/` 첫 화면 visible card count: 30
- 검색 결과도 30개 단위 표시
- 0건 검색어에서만 no-result UI 표시
- Invalid Date, NaN, undefined/null 노출 없음

개선점:
- `/support/?q=소상공인`에서 결과는 정상이나 검색 input 자체에는 현재 검색어가 유지되지 않는 것으로 확인됐다. 결과 헤더와 chip에는 검색어가 표시되므로 치명적이지는 않지만, 재검색 UX는 떨어진다.
- 카드의 badge가 많아진 상태다. category/status/source/official confirmation이 동시에 보이면 기업마당 정책에서는 다소 복잡하게 보인다.
- 카테고리 전용 페이지(`/category/small-business/`, `/category/startup/`)는 각각 387개, 335개 카드를 한 번에 렌더링한다. `/support/`와 달리 pagination이 없어 다음 성능 개선 후보이다.

## 상세 페이지 평가

상세 페이지는 이전 개선으로 핵심 요약, 지원 대상, 지원 내용, 신청 방법, 공식 출처가 명확히 보인다. description이 비어 있는 데이터도 기존 필드를 조합해 읽을 수 있는 구조가 유지된다.

좋은 점:
- 주요 상세 페이지 404 없음
- 제목/meta/canonical 구조 유지
- 지원 대상/지원 내용/신청 방법/공식 출처 노출
- Invalid Date, NaN, undefined/null 없음
- D-day/status/region guard 유지

개선점:
- "공식 공고 확인" 문구가 상세 페이지에서 여전히 10회 이상 반복되는 케이스가 있다. 단일 신뢰 블록은 생겼지만, 신청기간, 필요서류, 기본 정보, 확인 안내에 같은 문구가 반복되어 불안감을 줄 수 있다.
- Bizinfo 상세는 원문 공고 문장이 길어 summary, supportContent, amount, search text에 유사 내용이 반복되는 인상이 있다.
- 일부 Bizinfo 항목은 category가 틀리면 상세 breadcrumb도 틀린다. 예: 기술닥터사업이 `주거`로 표시됨.

## 카테고리 평가

가장 큰 품질 이슈는 카테고리다. 46단계에서 1차 Bizinfo 오분류를 정리했지만, 2차 batch 500개가 추가되면서 `주거` 카테고리에 기업지원 정책 26건이 다시 들어왔다.

Bizinfo category distribution:
- 소상공인: 350
- 창업: 297
- 교육: 162
- 고용: 134
- 농림어업: 30
- 주거: 26

문제:
- `주거` 26건은 대부분 중소기업, 수출, 융자, 기술지원, 인증, 청년기업 인증, 임차료 지원 등 기업지원 성격이다.
- 사용자가 주거 카테고리에서 전세/월세/임대주택 지원을 기대했을 때 기업마당 공고가 노출되면 신뢰도가 떨어진다.
- 소상공인/창업/고용/교육 분류는 대체로 작동하지만, 기술지원/수출/융자/인증/판로 항목은 별도 기업지원 taxonomy가 없어 소상공인으로 몰리거나 교육/고용으로 흩어진다.

권장:
- 배포 전 Bizinfo `주거` 26건을 최소 수정한다.
- 중장기적으로 `기업지원` 또는 `중소기업` 카테고리 신설을 검토한다.
- 현재 `소상공인` 카테고리가 중소기업/수출/R&D/기술지원까지 모두 떠안고 있어 의미가 넓어지고 있다.

## 검색 UX 평가

검색 결과 UX는 전반적으로 정상이다. 예를 들어 `소상공인` 검색은 1,009개 결과, `정책자금` 검색은 8개 결과로 표시되며, 0건 검색어에서는 no-result UI가 정상 노출된다.

좋은 점:
- 검색 결과 제목이 query/filter를 설명함
- 결과 count가 filtered result 기준
- 결과가 있을 때 no-result UI가 보이지 않음
- 번호형 pagination 정상

개선점:
- 검색 input에 현재 q 값이 유지되지 않는 것으로 확인됨
- 결과 정렬이 아직 "추천순"이라고 보이지만 실제 ranking 신호가 충분히 설명되지 않는다
- 기업마당 대량 유입 후 검색 결과 상단이 기업 공고 중심으로 많이 바뀌며, 개인 사용자가 찾는 복지성 검색어와 기업 지원 검색어의 결과 성격이 섞일 수 있다

## 가장 심각한 문제 TOP 10

1. Bizinfo 기업지원 26건이 `주거` 카테고리에 들어간 명백한 오분류
2. 카테고리 전용 페이지가 수백 개 카드를 한 번에 렌더링함
3. 상세 페이지에서 "공식 공고 확인" 문구가 여전히 과도하게 반복됨
4. 검색 input이 query parameter 값을 유지하지 않는 UX 문제
5. Bizinfo 상세에서 원문 문장이 여러 블록에 반복되어 읽기 피로가 있음
6. `소상공인` 카테고리가 중소기업, 수출, R&D, 기술지원까지 포괄해 의미가 넓어짐
7. `보건의료` category count가 440으로 커졌으나 기업마당 일부 의료기기/바이오 기업지원과 개인 의료복지가 섞일 가능성이 있음
8. 검색 결과 추천순의 기준이 사용자에게 명확하지 않음
9. 메인 최신 지원사업 카드가 사용자의 대표 진입 목적별로 충분히 큐레이션되어 있지 않음
10. 데이터 출처가 많아진 만큼 source filter가 정부24/복지로/K-Startup 중심으로 보이고 기업마당/온통청년 존재감이 약함

## 다음에 바로 할 작업 TOP 5

1. Bizinfo `주거` 오분류 26건을 소상공인/창업/고용/교육/농림어업 중 명확한 곳으로 재분류
2. `/category/*` 페이지에도 `/support/`와 같은 30개 단위 pagination 적용
3. 상세 페이지의 "공식 공고 확인" 반복을 한 단계 더 줄이고, 값 필드에는 짧은 label만 남기기
4. 검색 input에 현재 q 값을 다시 유지하도록 점검
5. Bizinfo 전용 카테고리 규칙을 강화하거나 `기업지원/중소기업` 상위 분류 신설 검토

## 3,088개 버전 배포 판단

기술적으로는 배포 가능하다. validate/test/build가 통과하고, 주요 페이지에서 Invalid Date, NaN, undefined/null, 404 문제는 발견되지 않았다.

하지만 제품 품질 관점에서는 바로 배포를 권장하지 않는다. 기업마당 2차 배치로 인해 `주거` 카테고리에 명백한 기업지원 공고 26건이 들어갔고, 이는 사용자가 카테고리 탐색을 신뢰하는 데 직접적인 영향을 준다.

최종 판단: `배포 전 카테고리 최소 수정 권장`.
